# 多遍深度安全扫描（deep-security-scan）— 兼容存根

> **已合并**：本技能内容并入 `security-audit`，对应它的 **deep 模式**（多轮迭代）。
> 新版入口：`security-audit` · 完整原文：`../security-audit/references/legacy-deep-security-scan.md`（仅当 `security-audit` 已安装时该路径存在；否则按下方「内联速查」执行）。
> 本目录保留用于旧引用兼容，触发词与语义不变；只需要一轮快速过检时，用 `security-audit` 的 **quick 模式**。

## 原来的定位（保留说明）

本 skill 适配**全栈、软件开发**团队的深度审计。它是「深扫」：在单遍快扫基础上做多轮迭代，沿数据流追踪污染源到 sink，画鉴权矩阵，挖业务逻辑漏洞。用于上线前、高风险模块、或快扫发现疑点后的深挖。

## 何时使用

- 上线前 / 重大发版前的深度安全门禁。
- 单遍快扫发现可疑点，需要确认是否真可利用。
- 涉及支付、权限、多租户隔离等高风险模块。
- 安全事件后的复盘加固。

## 怎么执行

1. 优先加载 `security-audit`，按「deep 模式：多轮迭代」五轮执行；严重度用它的「统一严重度」表，报告用它的「交付物」章节。
2. 先跑 quick 再升档时，在报告「范围与方法」里写明升档理由。
3. `security-audit` 不可用时（例如 `--profile dev` 只装白名单技能），按下面的「内联速查」原样执行，并在交付里说明「走的是存根内联流程」。

## 内联速查（security-audit 不可用时的等价流程）

五轮：**攻击面测绘**（列全部入口：HTTP 路由、RPC、消息消费、文件上传、定时任务，标信任边界）→ **污点追踪**（每个不可信输入追到 sink：SQL/命令/文件/响应，标注中间校验）→ **鉴权矩阵**（逐路由 × 逐角色，含对象级 IDOR 与租户隔离）→ **依赖与供应链**（递归查传递依赖漏洞与维护状态）→ **业务逻辑**（金额、状态机、并发竞态、重试幂等、配额绕过）。

报告固定五段：`## 范围与方法` → `## 已确认漏洞` → `## 待验证疑点` → `## 已排除项` → `## 修复优先级与上线建议`。每条确认漏洞给「位置 → 复现路径 → 影响 → 修复方案」；「已确认 / 待验证」是独立于严重度的置信维度，不许混列。

分级沿用原四档（Critical/High/Medium/Low，按实际可利用性定级）。门禁判据：每个外部输入都追到 sink 且校验点已确认有效；鉴权矩阵覆盖全部路由；传递依赖递归排查过；密钥溯源到 git 历史；业务逻辑边界已测；每个确认漏洞有最小复现步骤。
