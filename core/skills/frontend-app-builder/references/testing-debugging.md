# 前端测试与调试（E2E / 组件）

本 skill 适配**全栈团队**的前端质量保障。核心纪律：**先稳定复现再修**；测试断言用户能看到/能操作的行为，不断言内部 state 或实现细节；E2E 只覆盖关键路径，不追求每像素覆盖。

## 这是什么
一套前端测试分层与调试方法论。组件测试兜住交互逻辑，E2E 兜住主流程，调试时用 DevTools 从现象反查到根因，避免盲改 CSS 碰运气。

## 何时使用
- 为新组件/页面补测试。
- 线上/本地出现交互 Bug、样式错位、数据渲染不对。
- 关键流程（登录、下单、支付）需要 E2E 守护。

## 核心步骤
1. **分层选测试**：纯逻辑/hook 用单测；组件交互用组件测试；跨页面主流程用 E2E。
2. **断言行为**：测「点按钮后出现什么文字/发出什么请求」，不测「useState 变成几」。
3. **稳定选择器**：用 role / test-id / 文本定位，不依赖易变的 CSS 类或位置。
4. **先复现 Bug**：在浏览器里稳定重现，录下步骤，再动代码。
5. **分层定位**：是渲染问题（DOM/CSS）、状态问题（store/props）、还是网络问题（请求/响应）。
6. **修后回归**：修复同时补一个能复现该 Bug 的测试，锁住防复发。

## 测试清单
- [ ] 组件测试覆盖：渲染、交互触发、loading/error 态。
- [ ] E2E 覆盖关键用户旅程（登录→核心操作→结果可见），不写细枝末节。
- [ ] 选择器稳定（role/test-id/文本），不靠 class 名或坐标。
- [ ] 测试不依赖执行顺序，可独立跑、可并行。
- [ ] 异步等待用「等待元素出现」而非固定 `sleep`。
- [ ] 每个线上 Bug 修复都带回归测试。

## 调试流程
1. **复现**：固定步骤稳定复现，记录预期 vs 实际。
2. **看网络**：Network 面板确认请求发出、响应对不对、状态码。
3. **看状态**：组件/DevTools 检查 props、store、上下文是否符合预期。
4. **看渲染**：Elements 面板查 DOM 结构与计算样式，定位是数据错还是 CSS 错。
5. **二分定位**：注释/桩掉可疑模块，缩小范围，不一次性大改。
6. **验证**：修完在复现步骤上确认，并补回归测试。

## 易错点
- **断言实现细节**：测试内部 state 或函数调用次数，重构一次测试全红，脆弱无价值。
- **用 sleep 等异步**：固定等待慢且不稳，应等待目标元素/请求完成。
- **选择器脆**：靠 CSS 类名或元素位置定位，一改样式测试就挂。
- **不复现就改**：凭猜测改 CSS，刷新一下「好像好了」，换环境又复现。
- **E2E 写太细**：把每个表单字段都写成 E2E，跑几分钟还易 flaky。细粒度交给组件测试。
- **忽略 flaky**：测试时好时坏就跳过，实际是异步/隔离问题，必须根治。
- **网络问题当渲染问题**：数据没出来就去调样式，其实是接口没返回。
