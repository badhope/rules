# 前端应用脚手架与组件实现

本 skill 适配**全栈团队**的前端开发。目标：搭出结构清晰、可维护的前端工程，并按「数据层/视图层/状态层」分层实现组件，避免逻辑全堆在页面组件里、状态到处散落。

> **测试与调试分册**：`references/testing-debugging.md` 是原 `frontend-testing-debugging` 技能的完整正文。
> 内容：测试分层（单测/组件/E2E）、断言用户可见行为、稳定选择器、Bug 先复现再修的分层定位流程、易错点。
> 写完组件或排查交互/样式/数据渲染问题时读它；E2E 只覆盖关键路径，不追求每像素覆盖。

## 这是什么
一套前端工程化与组件设计规范。约定项目结构、路由/状态/数据获取的组织方式、组件拆分原则与构建优化手段，产出可运行的脚手架和具体组件实现。

## 何时使用
- 从零新建前端应用（选脚手架、定目录结构）。
- 实现新页面/组件，需要拆分与状态管理方案。
- 重构巨型组件、梳理数据获取层。

## 核心步骤
1. **定技术栈与约束**：框架（React/Vue 等）、路由、状态管理、样式方案、构建工具，一次选定不中途换。
2. **搭目录结构**：按功能域或类型分层，统一约定 components / hooks / services / pages / lib 归属。
3. **分层数据获取**：组件不直接 fetch，经 service/hook 层取数，组件只管渲染与交互。
4. **拆组件**：按单一职责拆，容器组件管数据、展示组件管 UI；props 明确、可复用。
5. **状态管理**：全局态（用户/权限）放 store，局部态留在组件，不滥用全局状态。
6. **构建与加载优化**：路由懒加载、按依赖分包、静态资源压缩，首屏体积可控。

## 工程清单
- [ ] 目录结构统一，新成员一看就知道文件放哪。
- [ ] 数据获取收敛在 service/hook 层，组件不散落 fetch。
- [ ] 路由表集中管理，受保护路由有鉴权守卫。
- [ ] 全局状态最小化，服务端数据用缓存层（query 库）而非全塞全局 store。
- [ ] 组件有 loading / error / empty 三态，不只渲染成功态。
- [ ] 表单有校验与错误提示，提交有防重复点击。
- [ ] 关键交互有可访问性（label、键盘可达、aria）。
- [ ] 首屏按路由/依赖分包，无巨型 bundle。

## 组件拆分原则
- 容器组件：取数、调度、处理状态；展示组件：纯渲染，props 输入。
- 一个组件只做一件事；超过 ~200 行且混杂数据与视图就拆。
- 副作用（请求、订阅）放进 hook，组件保持声明式。
- 列表渲染用稳定 key，不滥用数组下标作 key。

## 易错点
- **巨型组件**：一个页面组件又取数又渲染又算业务逻辑，几百行难维护。
- **到处直接 fetch**：组件里散落请求，接口改了要改十几处。统一走 service 层。
- **滥用全局状态**：把每个字段都塞 store，组件间依赖混乱。服务端数据交给缓存层。
- **只渲染成功态**：加载时空白、报错时白屏，没有 loading/error/empty 处理。
- **key 用下标**：列表增删时组件状态错乱，用稳定业务 id。
- **过度设计**：小项目也上全套状态管理 + 原子组件库。按规模选方案。
- **忽略可访问性与加载性能**：按钮无 label、首屏全量加载，上线后才补。
