# 多遍深度安全扫描（deep-security-scan）

本 skill 适配**全栈、软件开发**团队的深度审计。它是「深扫」：在单遍 `security-scan` 基础上做多轮迭代，沿数据流追踪污染源到 sink，画鉴权矩阵，挖业务逻辑漏洞。用于上线前、高风险模块、或快扫发现疑点后的深挖。

## 这是什么
多轮、基于数据流的深度安全审计。不满足于「找到危险函数」，而是追清楚：外部输入能否到达危险点、中间有没有校验、鉴权是否在每一层都生效。每一轮聚焦一个攻击面，迭代直到收敛。

## 何时使用
- 上线前 / 重大发版前的深度安全门禁。
- 单遍快扫发现可疑点，需要确认是否真可利用。
- 涉及支付、权限、多租户隔离等高风险模块。
- 安全事件后的复盘加固。

## 核心步骤（多轮迭代）
1. **第 1 轮：攻击面测绘**：列出所有入口（HTTP 路由、RPC、消息消费、文件上传、定时任务），标记信任边界。
2. **第 2 轮：污点追踪**：从每个不可信输入出发，追数据流到 sink（SQL/命令/文件/响应），标注中间有无校验/转义。
3. **第 3 轮：鉴权矩阵**：逐路由 × 逐角色列表格，标出谁能调、对象级权限是否校验，找越权/IDOR。
4. **第 4 轮：依赖与供应链**：不仅直接依赖，递归查传递依赖的已知漏洞与维护状态，核对 SCA 报告。
5. **第 5 轮：业务逻辑**：金额计算、状态机、并发竞态、重试幂等、配额绕过等逻辑层漏洞。
6. **收敛报告**：每个确认漏洞给「位置 → 复现路径 → 影响 → 修复方案」，区分已确认与待验证。

## 深度检查清单
- [ ] 每个外部输入都追到了 sink，污点路径上的校验点已确认有效。
- [ ] 鉴权矩阵覆盖全部路由，含对象级（IDOR）与租户隔离。
- [ ] 传递依赖漏洞已递归排查，不只看直接依赖。
- [ ] 密钥溯源到 git 历史，确认是否已泄露并需轮换。
- [ ] 业务逻辑：负数金额、状态倒挂、并发扣减、重放、配额绕过已测。
- [ ] 每个确认漏洞有最小复现步骤或 PoC 思路，不是「可能有问题」。
- [ ] 待验证项单独列出，不与已确认漏洞混为一谈。

## 输出报告结构
```
# 深度安全审计报告
## 范围与方法（扫了哪些入口、用了几轮、未覆盖部分）
## 已确认漏洞（critical/high，每条含位置/复现/影响/修复）
## 待验证疑点（有嫌疑但未证实，给出验证方法）
## 已排除项（快扫报了但确认不可利用，说明理由）
## 修复优先级与上线建议
```

## 易错点
- **把疑点当结论**：没跑通复现就报「存在 RCE」，实际被某层校验挡住。必须区分已确认与待验证。
- **只做输入输出不追中间**：找到了 `db.query(raw)`，却没看上面是否已有白名单校验，误报。
- **漏了非 HTTP 入口**：只测 Web 路由，忘了消息消费者、定时任务、导入接口这些同样是入口。
- **越权只测水平不测垂直**：查了普通用户能不能看别人数据，没查普通用户能不能调管理员接口。
- **忽略业务逻辑**：技术上全对，但「订单金额可传负数」这种逻辑漏洞扫不出来，必须人工推。
- **报告不可执行**：只说「存在注入风险」，不给位置和复现路径，开发无法修。
