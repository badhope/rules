# 单遍仓库安全审计（security-scan）

本 skill 适配**全栈、软件开发**团队的快速门禁。它是「快扫」：一遍过依赖、配置、源码里的常见高危模式，输出分级清单。需要深度链路追踪、数据流污点分析时，改用 `deep-security-scan`。

## 这是什么
一轮结构化的快速安全过检。用工具（依赖扫描、密钥扫描、静态规则）+ 人工 spot check 结合，在一次 passes 内把最可能出事的点捞出来，不追求穷尽。

## 何时使用
- PR 合入前的快速安全门禁。
- 接手陌生仓库的第一遍安全摸底。
- 发版前的冒烟式安全检查。

## 核心步骤
1. **依赖体检**：列出所有直接依赖，查已知 CVE / 弃用包 / 过期版本，区分可利用性。
2. **密钥与凭据扫描**：全局扫硬编码的 API Key、密码、token、私钥、Webhook 地址。
3. **注入与危险函数**：找 SQL 拼接、命令拼接、模板注入、反序列化、动态 eval。
4. **鉴权与会话**：检查路由是否漏鉴权、越权（IDOR）、JWT 校验缺失、CORS 过宽。
5. **配置与传输**：检查是否 debug 暴露、错误堆栈外泄、HTTPS 强制、安全响应头。
6. **分级输出**：按 critical / high / medium / low 出清单，每条给位置 + 风险 + 修复方向。

## 快速检查清单
- [ ] 依赖扫描无未修复 critical/high CVE，或有明确豁免理由。
- [ ] 仓库里无硬编码密钥（含历史提交、`.env.example` 外的真实值）。
- [ ] 数据库查询用参数化/ORM，无字符串拼接 SQL。
- [ ] 无 `exec`/`system` 拼接用户输入；文件路径做了白名单校验。
- [ ] 所有敏感路由有鉴权中间件；对象级权限在服务端校验，不只靠前端隐藏。
- [ ] 生产关闭 debug / 详细错误页；错误不返回堆栈/SQL。
- [ ] 上传文件校验类型/大小/扩展名，存储不可直接执行。
- [ ] 会话/令牌有过期、httponly、secure 标志。

## 风险分级约定
- **Critical**：可被远程直接利用拿数据/RCE（未授权注入、硬编码生产密钥）。
- **High**：鉴权缺失、越权访问他人数据、高危依赖漏洞。
- **Medium**：信息泄露、CORS 配置过宽、缺少安全头。
- **Low**：最佳实践类（日志脱敏不全、依赖补丁滞后）。

## 易错点
- **只跑工具不人工看**：工具报一堆误报，不做甄别就全列上去，淹没真问题。
- **只扫工作区不扫历史**：密钥曾提交过，即便现在删了也已泄露，必须轮换。
- **把「理论风险」当 critical**：脱离实际可利用性分级，导致门禁噪音过大。
- **越权只看登录态不看对象级**：检查了「要登录」却没查「能不能看别人的订单」（IDOR）。
- **依赖漏洞不看版本范围**：报了 CVE 但当前版本不在受影响范围，误报为高危。
- **快扫当深扫用**：单遍扫不出复杂数据流污点问题；发现疑点要升级到 deep-security-scan。
