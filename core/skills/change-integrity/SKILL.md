# 改动完整性（Change Integrity）

解决的问题：**看一段改一段 → 再看又冒出新问题 → 跑个测试就说好了 → 其实没修好、没改完、没效果**。

根因有三个，对应三道防线：

| 根因 | 表现 | 防线 |
|---|---|---|
| 没有全局模型就开始改 | 改 A 坏 B，反复打补丁 | 改动前建模（影响面清单） |
| 验证只看「有没有报错」 | 0 测试、全 skip、弱断言也算绿 | 反证验证（test the test） |
| 用「测试通过」代替「目标达成」 | 测试绿了但用户看到的问题还在 | 效果验证（改前改后对比） |

## 第一道：改动前先建模

**禁止**在没搞清影响面的情况下动第一行代码。

### 三分钟建模

```markdown
【影响面】
- 目标行为改变：<从什么变成什么>
- 直接相关文件：<列出>
- 间接依赖方：<谁调用它、谁读它的数据、谁依赖它的副作用>
- 共享状态：<全局变量/缓存/单例/数据库表/配置项>
- 并发与顺序：<是否依赖调用顺序、是否有竞态>
- 失败路径：<异常时谁受影响、错误如何传播>
- 不改的部分：<明确声明本次不碰什么>
```

建模的产出必须写进记忆文件或计划，不能只在脑子里。

### 一次改透 vs 反复打补丁

| 反复打补丁（反模式） | 一次改透 |
|---|---|
| 改一处 → 跑 → 又报错 → 改另一处 | 先列出所有需要同步改的点，一次改完 |
| 只修报错的那一行 | 修根因 + 修同类问题 + 加回归测试 |
| 每次改都重新理解上下文 | 建模一次，后续按清单执行 |

**判定标准**：如果同一个功能你改了 3 次以上还在修，说明第一次就没建模——停下来重新建模，不要继续打补丁。

## 第二道：反证验证（test the test）

**测试通过不代表测试有效。** 一个永远不会失败的测试，和一个没有测试是一样的。

### 反证三问

每次声称「验证通过」前，必须能回答：

1. **这个测试真的跑了吗？** 不是 0 个测试、不是全 skip、不是被配置排除。
2. **它真的会失败吗？** 把被测代码改坏，测试必须变红。如果改坏了还是绿，测试无效。
3. **它测的是行为还是实现？** 断言输出与副作用，不是断言「函数被调用过」。

### 假绿识别清单

| 假绿信号 | 为什么可疑 | 怎么查 |
|---|---|---|
| `0 tests` / `no tests found` | 测试根本没跑 | 检查测试路径与命名匹配 |
| 全部 `skipped` / `todo` | 被条件排除 | 查 `.only` / `skip` / 环境判断 |
| 只断言 `not.toThrow()` | 出错才失败，逻辑错也过 | 补具体期望值 |
| 断言 `expect(true).toBe(true)` | 恒真 | 删掉，写真实断言 |
| mock 掉了被测逻辑本身 | 测的是 mock 不是代码 | 只 mock 外部边界 |
| 覆盖率 100% 但无断言 | 执行了但没验证 | 看断言数量与质量 |
| 测试与实现同一人同一轮写的 | 容易迁就实现 | 用需求反推用例 |

### 反证操作（推荐做法）

改坏 → 看红 → 改回 → 看绿。

```bash
# 1. 记录当前测试通过
npm test        # 绿

# 2. 故意改坏被测逻辑（如把返回值改成 null）
# 3. 再跑
npm test        # 必须红；如果还绿，测试无效

# 4. 改回
npm test        # 恢复绿
```

小改动可以手工做这一轮；核心逻辑建议固化成脚本。

## 第三道：效果验证

**测试绿 ≠ 用户的问题解决了。** 最后一问：改之前用户看到的现象，现在真的变了吗？

### 三种证据，缺一不可

| 证据 | 形式 | 回答什么 |
|---|---|---|
| 行为证据 | 复现步骤 + 改前/改后输出 | 用户的问题真的没了吗 |
| 回归证据 | 全量测试结果 | 有没有弄坏别的 |
| 边界证据 | 空态/异常/并发下的表现 | 只在正常路径有效吗 |

只有回归证据、没有行为证据时，**不能宣称「修好了」**，只能说「测试通过」。

### 效果对比模板

```markdown
【效果验证】
- 原问题：<复现步骤>
- 改前：<实际输出/现象>
- 改后：<实际输出/现象>
- 回归：<全量测试结果，含数量>
- 未覆盖：<哪些场景没验证，为什么>
```

## 第四道：完成度对账

「改完了」的定义不是「我不报错了」，而是**原始需求的每一条都有证据**。

- [ ] 需求逐条列出，每条对应一个可观察结果
- [ ] 每个结果有命令输出或截图作证
- [ ] 明确列出「没做的部分」与原因
- [ ] 没有「应该可以」「理论上没问题」这类措辞

## 反模式对照

| 说法 | 问题 | 应该说 |
|---|---|---|
| 「测试都过了」 | 没说是几个、是否有效 | 「12 个测试通过，其中 3 个是新增的回归用例」 |
| 「应该没问题了」 | 没有证据 | 「按 X 步骤复现，改前报错 Y，现在输出 Z」 |
| 「主要逻辑改好了」 | 没改完 | 「改了 A/B/C 三处，D 未改，原因是…」 |
| 「我再看一下」 | 没有全局模型 | 「影响面是这些，我一次改完」 |

## 与其它技能衔接
